# KnuZoom 구현 계획서 — 추적 카메라 확대 연동 자동 음소거 해제

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** B대학 회의실 추적 카메라가 발언자 쪽으로 확대되면 Zoom Workplace 마이크를 자동으로 음소거 해제하고, 넓은 장면으로 돌아가면 음소거하는 Windows 보조 프로그램을 만든다.

**Architecture:** KnuZoom이 카메라를 받아 원본을 가상 카메라로 Zoom에 넘기고, 같은 영상을 초당 5회 얼굴 검출로 분석해 WIDE/ZOOM을 판정한다. 판정은 상태 확정기를 거쳐 안정 상태가 되고, 상태가 바뀔 때만 Zoom 제어기가 UI Automation으로 현재 마이크 상태를 확인한 뒤 Alt+A를 보낸다. 판단 로직(판정·확정·보정·제어·엔진)은 순수 Python으로 분리해 Linux에서도 단위 시험하고, Windows 의존부(카메라·가상카메라·Zoom 어댑터·화면)는 얇게 유지해 B대학 PC에서 수동 검증한다.

**Tech Stack:** Python 3.11, pytest, OpenCV(`opencv-python`), MediaPipe(`mediapipe==0.10.14`, `mp.solutions.face_detection`), pyvirtualcam(OBS Virtual Camera 드라이버), pywinauto(UIA backend), keyboard(전역 단축키), tkinter, pystray, PyInstaller

**Spec:** `docs/superpowers/specs/2026-10-18-knuzoom-design.md`

## Global Constraints

- 대상 OS: Windows 10/11. 판단 로직 모듈(`config`, `detector`, `stabilizer`, `calibration`, `mic`, `engine`, `video_io`)은 Windows 전용 패키지를 import하지 않는다.
- 분석 주기: 초당 약 5회(`analysis_fps=5`). 가상 카메라 출력은 원본 30fps 유지.
- ZOOM: H ≥ 0.22 그리고 N ≤ 2 / WIDE: H ≤ 0.15 또는 N ≥ 3 / 그 외·얼굴 미검출: 불확실. 평가 순서 ZOOM → WIDE → 불확실.
- WIDE→ZOOM: 최근 1.0초 판정 중 ZOOM ≥ 80%. ZOOM→WIDE: 최근 1.5초 판정 중 WIDE ≥ 80%. 불확실은 분모에 포함.
- 시작 상태는 항상 WIDE(음소거).
- 보정: 각 장면 약 2초간 H 중앙값. d = H_zoom − H_wide, WIDE 기준 = H_wide + d×0.3, ZOOM 기준 = H_wide + d×0.7. H_zoom ≤ H_wide이면 기존 값 유지 + 경고.
- Zoom 제어: 원하는 상태 ≠ 현재 상태일 때만 Alt+A. 1초 후 재확인, 다르면 1회 재시도, 그래도 다르면 경고.
- 오류 원칙: 장비·시스템 오류 → 음소거 / 판정 애매 → 현재 상태 유지.
- 긴급 정지 기본 단축키 `ctrl+alt+k` (설정 가능).
- 영상·얼굴 정보는 저장하지 않는다. 로그는 `HH:MM:SS 이전→이후 결과` 형식의 상태 전환만 기록한다(예: `10:32:05 WIDE→ZOOM 해제 성공`).
- 화면·경고 문구(한국어 고정): "발언 가능", "음소거", "카메라 끊김", "대기", "호스트(A대학)가 해제를 막았을 수 있음", "음소거 실패", "상태 추정 중(Zoom 상태를 읽을 수 없음)", "보정 실패: 확대 장면이 넓은 장면보다 커야 합니다", "오류 발생".

## Review Focus

1. 얼굴 0개(빈 회의실, 뒤돌아봄): H=0이 WIDE 기준(≤0.15)에 걸려 WIDE로 오판하면 안 되고 **불확실**이어야 한다 → Task 2 `test_no_face_is_uncertain`.
2. 시작 직후·카메라 복구 직후처럼 이력이 창 길이보다 짧을 때: 첫 ZOOM 장면 1장만으로 해제되면 안 된다 → Task 3 `test_needs_full_window_of_history`.
3. KnuZoom을 먼저 켜고 나중에 Zoom 회의에 들어온 경우: 들어오는 순간 현재 원하는 상태(기본 음소거)가 적용돼야 한다 → Task 6 `test_pending_state_applied_when_meeting_appears`.
4. 자동 OFF 중 카메라가 확대됐다가 자동을 다시 켠 경우: 다시 켜는 시점의 안정 상태가 적용돼야 한다 → Task 6 `test_auto_on_applies_current_state`.
5. 카메라가 끊겼다가 복구된 경우: 끊김 시 음소거·확정기 WIDE 초기화, 복구 후 경고가 사라지고 새 이력으로만 해제돼야 한다 → Task 6 `test_camera_recovery_clears_warning_and_requires_new_history`.

### Task 3: 상태 확정기(stabilizer)

**Files:**
- Create: `src/knuzoom/stabilizer.py`
- Test: `tests/test_stabilizer.py`

**Interfaces:**
- Consumes: `Verdict`, `Settings`
- Produces: `class Stabilizer(s: Settings)` — 속성 `state: Verdict` (WIDE 또는 ZOOM만, 초기 WIDE), `update(t: float, v: Verdict) -> Verdict | None` (전환 시 새 상태 반환, 아니면 None), `reset(t: float) -> None` (상태 WIDE, 이력 비움)

규칙(테스트가 정하지 않는 부분):
- 현재 상태가 WIDE면 창 = `unmute_window_s`, 목표 = ZOOM. ZOOM이면 창 = `mute_window_s`, 목표 = WIDE.
- 창 판정: `t − window < 표본시각 ≤ t` 인 표본 중 목표 판정 비율 ≥ `ratio`.
- 기준 시각 `ref`: 생성·`reset` 후 첫 표본 시각, 전환이 일어나면 그 전환 시각으로 갱신. `ref ≤ t − window`가 아니면 전환하지 않는다(이력 부족).
- 전환 후에도 이력(deque)은 비우지 않는다.

- [ ] **Step 1: 실패하는 테스트 작성** (헬퍼 `feed(st, seq, t0=0.0, dt=0.2)`는 각 판정을 0.2초 간격으로 넣고 전환 결과 목록을 돌려준다)

```python
def test_starts_wide():
    assert Stabilizer(Settings()).state is Verdict.WIDE

def test_needs_full_window_of_history():  # Review Focus 2
    st = Stabilizer(Settings())
    assert st.update(0.0, Verdict.ZOOM) is None
    assert st.update(0.2, Verdict.ZOOM) is None
    assert st.state is Verdict.WIDE

def test_unmute_after_one_second_of_zoom():
    st = Stabilizer(Settings())
    out = feed(st, [Verdict.ZOOM] * 6)          # t=0.0..1.0
    assert out[-1] is Verdict.ZOOM and st.state is Verdict.ZOOM

def test_brief_zoom_does_not_unmute():
    st = Stabilizer(Settings())
    feed(st, [Verdict.WIDE] * 10)
    feed(st, [Verdict.ZOOM] * 3 + [Verdict.WIDE] * 5, t0=2.0)
    assert st.state is Verdict.WIDE

def test_uncertain_counts_against():
    st = Stabilizer(Settings())
    feed(st, [Verdict.ZOOM, Verdict.UNCERTAIN] * 10)
    assert st.state is Verdict.WIDE

def test_mute_needs_one_and_half_seconds():
    st = Stabilizer(Settings())
    feed(st, [Verdict.ZOOM] * 6)                # → ZOOM at t=1.0
    feed(st, [Verdict.WIDE] * 7, t0=1.2)        # t=1.2..2.4 (1.2s) → 유지
    assert st.state is Verdict.ZOOM
    feed(st, [Verdict.WIDE] * 2, t0=2.6)        # t=2.6에서 (1.1, 2.6] 창 충족
    assert st.state is Verdict.WIDE

def test_face_lost_while_zoomed_keeps_unmuted():
    st = Stabilizer(Settings())
    feed(st, [Verdict.ZOOM] * 6)
    feed(st, [Verdict.UNCERTAIN] * 50, t0=1.2)
    assert st.state is Verdict.ZOOM

def test_reset():
    st = Stabilizer(Settings())
    feed(st, [Verdict.ZOOM] * 6)
    st.reset(5.0)
    assert st.state is Verdict.WIDE
    assert st.update(5.2, Verdict.ZOOM) is None
```

### Task 5: 마이크 제어기(MicController) — 가짜 어댑터로 시험

**Files:**
- Create: `src/knuzoom/mic.py`
- Test: `tests/test_mic.py`

**Interfaces:**
- Produces:
  - `class ZoomAdapter(Protocol)`: `meeting_active() -> bool`, `read_muted() -> bool | None` (읽을 수 없으면 None), `press_toggle() -> None`
  - `class ApplyResult(Enum): OK, NO_MEETING, BLOCKED, FAILED, ESTIMATED`
    - BLOCKED: 해제를 원했는데 재시도 후에도 음소거 / FAILED: 음소거를 원했는데 재시도 후에도 해제
  - `class MicController(adapter: ZoomAdapter, verify_delay_s: float, sleep: Callable[[float], None] = time.sleep)`:
    `apply(want_muted: bool) -> ApplyResult`, `sync_estimate(muted: bool) -> None` ([상태 맞추기]), 속성 `estimated_muted: bool` (초기 True)

동작: 회의 없음 → NO_MEETING(누르지 않음). `read_muted()`가 None → 예비 모드: `estimated_muted != want`일 때만 1회 누르고 `estimated_muted = want`, ESTIMATED. 읽기 가능 → 같으면 OK(누르지 않음), 다르면 누름 → `sleep(verify_delay_s)` → 재확인 → 같으면 OK, 다르면 1회 더 누름 → sleep → 재확인 → OK 또는 BLOCKED/FAILED. 결과가 OK이면 `estimated_muted = want`.

- [ ] **Step 1: 실패하는 테스트 작성** — `FakeZoom(muted=True, active=True, readable=True, stuck=False)`: `press_toggle()`은 `presses`를 1 늘리고 `stuck`이 아니면 `muted`를 뒤집는다.

정책:
- 시작: `muted=True`, `pending=True` (첫 `tick`/`on_stats`에서 음소거 적용 시도).
- 확정기 전환 시: `muted = (새 상태 is WIDE)`, `auto`이면 즉시 적용, 아니면 아무것도 보내지 않음.
- 적용 결과 → 경고: OK/ESTIMATED는 경고 해제(ESTIMATED는 "상태 추정 중(Zoom 상태를 읽을 수 없음)"), NO_MEETING → "대기" + `pending=True`, BLOCKED → "호스트(A대학)가 해제를 막았을 수 있음", FAILED → "음소거 실패". `pending`은 OK/ESTIMATED/BLOCKED/FAILED에서 해제.
- 진행자 수동 조작 존중: 전환·pending이 없을 때는 아무것도 보내지 않는다(별도 감시 없음).
- 카메라 끊김: 확정기 `reset`, `muted=True`, 즉시 적용(auto 여부와 무관), 경고 "카메라 끊김". 이후 `on_stats`가 다시 들어오면 경고 해제.
- 내부 오류: `muted=True` 적용 시도, 경고 "오류 발생".
- `set_auto(True)`: 현재 확정 상태로 `muted`를 맞추고 적용. `set_auto(False)`: 보내지 않음.
- `emergency_stop()`: `auto=False`, `muted=True`, 즉시 적용.
- 로그: 확정기 전환·카메라 끊김·긴급 정지 시 `f"{clock_hms()} {이전}→{이후} {결과}"` 형식. 결과 문구: 해제 성공 / 음소거 성공 / 해제 차단 / 음소거 실패 / 대기 / 추정 적용. 예: `10:32:05 WIDE→ZOOM 해제 성공`.
