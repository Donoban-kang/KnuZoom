# KnuZoom 설계서 — 추적 카메라 확대 연동 자동 음소거 해제

- 작성일: 2026-10-18
- 상태: 검토 대기
- 대상: B대학 화상회의실 Windows PC

## 1. 목적과 배경

### 1.1 상황
- A대학이 주최(호스트)하는 Zoom 화상회의에 B·C·D대학이 참가한다. 화면은 4분할 갤러리로 보인다.
- 우리는 **B대학(참가자)** 이며, 회의실에서 Zoom Workplace를 사용한다.
- B대학 회의실의 **자동 추적 카메라**는 여러 사람을 넓게 비추다가, 발언자가 생기면 스스로 발언자 쪽으로 확대한다.

### 1.2 원하는 동작
| 카메라 상태 | B대학 Zoom 마이크 |
|---|---|
| 넓게(여러 사람이 보임) | 음소거 |
| 발언자 쪽으로 확대 | 음소거 해제(발언 가능) |

### 1.3 성공 기준
- 진행자가 마이크 버튼을 누르지 않아도, 카메라가 확대되면 발언 가능한 상태가 된다.
- 다른 대학(A·C·D)의 화면·소리에는 영향을 주지 않는다.

### 1.4 선행 조건
- A대학(호스트)이 회의에서 **참가자 스스로 음소거 해제**를 허용해야 한다. 허용하지 않으면 어떤 방식으로도 자동 해제가 불가능하다(Zoom 정책상 본인 마이크 해제는 호스트 설정의 제약을 받는다).
- 기관 PC에 가상 카메라 드라이버 설치 허용 여부를 전산 담당 부서에 확인한다.
- 얼굴 검출 사용에 대해 기관 개인정보 담당 부서의 사전 확인을 권장한다(일반적인 공공기관 절차 기준이며, 기관 확정 절차는 별도 확인).

### 1.5 가정
- 회의용 PC는 Windows 10/11이다.
- 추적 카메라는 USB 또는 HDMI 캡처장치로 PC에 연결되며, 현재 Zoom이 직접 사용 중이다.

## 2. 선택한 방식

| 영역 | 선택 | 비교했던 대안 |
|---|---|---|
| 확대 상태 감지 | **영상 분석**(얼굴 수·크기로 판정) | 카메라에 IP 제어 명령(VISCA 등)으로 확대값 조회 — 카메라 모델 의존성 때문에 미채택 |
| 마이크 제어 | **Zoom Workplace 유지 + Alt+A 단축키 입력 + 상태 확인** | Meeting SDK 전용 접속 프로그램 — 개발량·계정/인증 부담으로 미채택 (상태 꼬임이 실사용에서 문제되면 재검토) |

## 3. 전체 구조

Windows에서 USB 카메라는 보통 한 프로그램만 열 수 있으므로, KnuZoom이 카메라를 먼저 받고 같은 영상을 가상 카메라로 Zoom에 넘긴다.

```
[추적 카메라] → [KnuZoom]
                  ├─ ① 영상 입출력: 원본을 가상 카메라 "KnuZoom Camera"로 그대로 출력 → Zoom이 이 카메라 사용
                  ├─ ② 확대 판단기: 장면별 WIDE / ZOOM / 불확실 판정
                  ├─ ③ 상태 확정기: 유지 시간 조건으로 안정 상태 확정
                  └─ ④ Zoom 제어기: 마이크 상태 확인 후 필요 시 Alt+A
                         WIDE → 음소거 / ZOOM → 음소거 해제
```

### 3.1 모듈
| 모듈 | 책임 | 입력 → 출력 | 기술 후보 |
|---|---|---|---|
| 영상 입출력 | 카메라 캡처, 가상 카메라 출력(30fps 원본 유지) | 카메라 장치 → 프레임 / 가상 카메라 | OpenCV, pyvirtualcam(OBS 가상카메라 드라이버) |
| 확대 판단기 | 한 장면의 판정 | 프레임 → (N, H, 판정) | MediaPipe 얼굴 검출 |
| 상태 확정기 | 순간 판정을 안정 상태로 확정 | (시각, 판정) 시계열 → WIDE/ZOOM 전환 이벤트 | 순수 로직 |
| Zoom 제어기 | 원하는 마이크 상태로 맞춤 | 원하는 상태 → 결과(성공/차단/불명) | Windows UI Automation, 키 입력(SendInput) |
| 진행자 화면 | 상태 표시, 자동 ON/OFF, 보정, 설정 | 사용자 조작 ↔ 각 모듈 | 소형 창 + 트레이 아이콘 |
| 설정 | 기준값·유지시간·버튼 문구·단축키 저장 | 설정 파일 | JSON/YAML |

각 모듈은 독립적으로 시험 가능해야 하며, 확대 판단기·상태 확정기·Zoom 제어기의 판단 로직은 Windows 의존 부분과 분리한다(Zoom 제어기는 "Zoom 어댑터" 인터페이스 뒤에 실제/가짜 구현을 둔다).

- 구현 언어: Python. 배포는 Windows 실행파일(.exe).

## 4. 확대 판단 규칙

### 4.1 장면 판정 (분석 주기: 초당 약 5회)
- N: 검출된 얼굴 수
- H: 가장 큰 얼굴의 높이 ÷ 화면 높이

| 판정 | 조건(초기값, 설정 가능) |
|---|---|
| ZOOM | H ≥ 22% 그리고 N ≤ 2 |
| WIDE | H ≤ 15% 또는 N ≥ 3 |
| 불확실 | 위 둘에 해당하지 않음, 또는 얼굴 미검출 |

조건 평가 순서: ZOOM 조건을 먼저 확인하고, 해당하지 않으면 WIDE, 둘 다 아니면 불확실. ZOOM과 WIDE 기준 사이의 간격(히스테리시스)으로 경계 진동을 막는다.

### 4.2 상태 확정
| 전환 | 조건(초기값, 설정 가능) |
|---|---|
| WIDE → ZOOM (음소거 해제) | 최근 1.0초 창의 판정 중 ZOOM이 80% 이상 |
| ZOOM → WIDE (음소거) | 최근 1.5초 창의 판정 중 WIDE가 80% 이상 |

- 불확실 판정은 비율 계산의 분모에 포함한다(불확실이 많으면 전환하지 않음 → 현재 상태 유지).
- 시작 상태는 항상 **WIDE(음소거)** 이다.

### 4.3 보정(캘리브레이션)
1. [넓은 장면 저장]: 현재 장면 약 2초간의 H 중앙값 = H_wide
2. [확대 장면 저장]: 현재 장면 약 2초간의 H 중앙값 = H_zoom
3. 두 값이 모두 있고 H_zoom > H_wide이면: 간격 d = H_zoom − H_wide, WIDE 기준 = H_wide + d×0.3, ZOOM 기준 = H_wide + d×0.7 로 설정한다. 조건을 만족하지 않으면 기존 값을 유지하고 경고한다.

## 5. Zoom 제어

1. Zoom.exe 프로세스의 회의 창을 찾는다.
2. Windows UI Automation으로 음소거 버튼의 이름을 읽어 현재 상태를 판단한다(예: "Unmute my audio" / "오디오 음소거 해제"). 문구는 Zoom 언어·버전에 따라 다르므로 설정 파일에서 지정한다.
3. 원하는 상태 ≠ 현재 상태일 때만 Alt+A를 보낸다.
4. 1초 후 상태를 다시 읽는다. 다르면 1회 재시도, 그래도 다르면 경고한다.
5. **예비 모드**: 상태를 읽을 수 없으면 KnuZoom이 마지막으로 보낸 명령으로 상태를 추정하고, 진행자가 [상태 맞추기]로 보정한다.
6. 사전 설정: Zoom 설정 > 키보드 단축키에서 Alt+A "전역 단축키" 사용.

## 6. 오작동 대응

원칙: **장비·시스템 오류 → 음소거**, **판정이 애매함 → 현재 상태 유지**.

| 상황 | 동작 |
|---|---|
| 카메라 연결 끊김 | 즉시 음소거 시도 + 경고 |
| KnuZoom 내부 오류 | 음소거 시도 + 빨간 경고 |
| 확대 중 얼굴이 사라짐(고개 숙임 등) | 불확실 → 해제 상태 유지 |
| Zoom 미실행/회의 아님/창 없음 | 동작하지 않고 "대기" 표시 |
| 해제 명령 후 1초 뒤에도 음소거 | "호스트(A대학)가 해제를 막았을 수 있음" 안내 |
| 진행자가 Zoom에서 직접 마이크 조작 | 그 조작을 존중. 다음 상태 전환 때부터 자동 제어 재적용 |
| 자동 OFF(일시정지) | 자동 제어 중단, 수동 운영 |
| 긴급 정지 단축키(기본 Ctrl+Alt+K) | 자동 OFF + 즉시 음소거. 정지 당시 확대 상태였다면 자동을 다시 켜도 음소거 유지, 넓은 장면을 거쳐 새로 확대될 때부터 자동 해제("긴급 정지 후 대기" 표시) |

## 7. 진행자 화면

- 항상 위에 표시되는 소형 창 + 트레이 아이콘
- 표시: 마이크 상태(초록 "발언 가능" / 빨강 "음소거"), 현재 판정(WIDE/ZOOM/불확실, H, N), 경고 문구
- 조작: [자동 ON/OFF], [상태 맞추기], [넓은 장면 저장], [확대 장면 저장], 설정(카메라 선택·기준값·유지시간·버튼 문구·단축키)
- 선택: 미리보기(얼굴 박스 표시, 화면 표시만 하고 저장하지 않음)

## 8. 개인정보

- 영상·얼굴 정보는 메모리에서만 처리하고 저장하지 않는다.
- 얼굴 **검출**만 하며 신원 식별은 하지 않는다.
- 로그에는 시각과 상태 전환만 기록한다(예: `10:32:05 WIDE→ZOOM 해제 성공`).

## 9. 시험

| 단계 | 내용 | 환경 |
|---|---|---|
| ① 단위 시험(TDD) | 판정기(N,H→판정), 상태 확정기(시계열→전환), 보정 계산, Zoom 제어기(가짜 어댑터로 확인→전송→재확인·재시도·예비 모드) | 개발 환경(Linux 가능) |
| ② 녹화 영상 재생 | 동의받은 리허설 영상으로 판정 정확도·전환 시간 측정, 시험 후 영상 삭제 | 개발 PC |
| ③ 실회의 리허설 | 테스트 계정 2개로 Zoom 회의, 호스트 "스스로 해제 허용" ON/OFF 각각 시험 | B대학 Windows PC |

### 9.1 합격 기준(초안)
- 카메라 확대 후 2.5초 이내 음소거 해제
- 넓은 장면 30분 유지 시 잘못된 해제 0회
- 카메라 연결 해제 시 즉시 음소거
- 긴급 정지 1초 이내 동작

## 10. 알려진 한계와 위험

| 항목 | 내용 | 대응 |
|---|---|---|
| 발언 앞부분 잘림 | 추적 카메라가 말을 듣고 확대한 뒤 1초 확정 → 첫 1~2초 잘릴 수 있음 | 구조적 한계로 수용, 유지시간 조정 가능 |
| UI Automation 상태 읽기 | Zoom 버전에 따라 불가할 수 있음(추가 확인 필요) | 예비 모드 + [상태 맞추기] |
| 전역 단축키 | Zoom 설정 필요(추가 확인 필요) | 설치 안내서에 포함 |
| 가상 카메라 드라이버 | 기관 보안 정책상 설치 제한 가능 | 전산 부서 사전 확인 |
| 호스트 정책 | A대학이 스스로 해제를 막으면 동작 불가 | 회의 전 A대학과 협의, 차단 시 안내 |
